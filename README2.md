# موتورِ Align (مرحله‌ی ۱ از پایپ‌لاین)

اسکریپتِ `align_batch.py` برای هر جفتِ (صدا + متن) در دو پوشه، تراز‌بندیِ خودکارِ کلمه‌به‌کلمه انجام می‌دهد و دو فایل تولید می‌کند:

- `<نام‌فایل>_markers.txt` → متنِ آماده با سینتکسِ `[ms]` برای پیست در ردیفِ دومِ جدولِ Word
- `<نام‌فایل>_draft.json` → پیش‌نویسِ ساختاریافته (کلمات + مرزهای زمانی + امتیازِ اطمینانِ هرکلمه) برای بارگذاری در ابزارِ WPF جهتِ مرور/اصلاح

## نصب (ویندوز)

۱. Python 3.10 یا بالاتر نصب باشد.
۲. **FFmpeg** باید نصب و در PATH باشد (کتابخانه‌ی align از آن برای دیکد کردنِ صدا استفاده می‌کند). می‌توانید از [gyan.dev/ffmpeg/builds](https://www.gyan.dev/ffmpeg/builds/) دانلود کنید یا با `winget install ffmpeg` نصب کنید، سپس پوشه‌ی `bin`اش را به PATH اضافه کنید.
۳. نصبِ وابستگی‌ها:

```bash
pip install -r requirements.txt
```

این دستور PyTorch، Transformers، و کتابخانه‌ی `ctc-forced-aligner` را نصب می‌کند. اولین اجرا، مدلِ align را از HuggingFace دانلود می‌کند (چند صد مگابایت، فقط یک‌بار).

اگر کارتِ گرافیکِ NVIDIA دارید، PyTorch با CUDA سریع‌تر است؛ بدونِ GPU هم روی CPU کار می‌کند، فقط کندتر (برای یک فایلِ چند‌دقیقه‌ای، چیزی حدودِ ۱۰-۳۰ ثانیه روی CPU معمولی).

## ساختارِ پوشه‌ها

از این به بعد نیازی به سه پوشه‌ی جدا نیست — همه‌چیز در **یک پوشه به‌نامِ `share`** کنارِ خودِ `align_batch.py`:

```
align_engine/
  align_batch.py
  share/
    MindsetIELTS_L3_09.mp3
    MindsetIELTS_L3_09.docx     <- همان سندِ دوردیفه‌ای که برای CustomLayoutGenerator/AudioMarkerReview هم استفاده می‌کنید (بدونِ مارکر)
    (یا)
    MindsetIELTS_L3_09.txt      <- یا صرفاً متنِ دقیق و کامل، بدونِ مارکر
    output/                     <- خودکار ساخته می‌شود، خروجی‌ها این‌جا می‌روند
```

نام‌ِ فایل‌ها باید (بدونِ پسوند) دقیقاً یکی باشند تا جفت‌شان تشخیص داده شود. اگر هم `.docx` هم `.txt` با همین نام موجود باشند، `.docx` در اولویت است.

با `.docx`، اسکریپت متنِ ردیفِ دومِ اولین جدولِ دوردیفه‌ی معتبر (ردیفِ اول = نامِ ترک، غیرِخالی) را می‌خواند — دقیقاً همان جدولی که CustomLayoutGenerator و ابزارِ WPF هم پیدا می‌کنند. اگر سند چند جدول/ترک دارد، فقط اولی خوانده می‌شود؛ برای بیش از یک ترک، هر کدام را در فایلِ Word جداگانه نگه دارید.

**نکته:** خروجیِ این مرحله (`_markers.txt`) الان بیشتر برای پیش‌نمایشِ سریع است — استایل‌ها را نگه نمی‌دارد. اگر سندِ اصلی‌تان فرمت‌بندی (بولد/ایتالیک/رنگ) دارد و می‌خواهید حفظ شود، مارکرها را با ابزارِ WPF مستقیم در یک کپی از همان `.docx` بنویسید (گزینه‌ی «Export to Word...» در نسخه‌ی جدیدِ ابزار) — راهنما در `wpf_review_tool/README.md`.

## اجرا

پوشه‌ی `share` را خودتان بسازید (کنارِ `align_batch.py`)، فایل‌های صوت+متن را داخلش بگذارید، و بدونِ هیچ آرگومانی اجرا کنید:

```bash
python align_batch.py
```

خروجی در `share/output` قرار می‌گیرد. یک پیامِ خلاصه هم برای هر فایل چاپ می‌شود، از جمله تعدادِ کلماتِ «کم‌اطمینان» (که بهتر است در ابزارِ WPF بررسی شوند).

### اگر هنوز می‌خواهید پوشه‌های جدا

آرگومان‌های قدیمی هنوز کار می‌کنند — هرکدام را بدهید، همان جای پیش‌فرض (`share` یا `share/output`) را override می‌کند؛ بقیه همچنان از `share` می‌آیند:

| آرگومان | توضیح |
|---|---|
| `--share_dir <مسیر>` | به‌جایِ پوشه‌ی `share`ِ کنارِ اسکریپت، یک مسیرِ دیگر |
| `--audio_dir <مسیر>` | فقط پوشه‌ی صدا را جدا کن |
| `--text_dir <مسیر>` | فقط پوشه‌ی متن/docx را جدا کن |
| `--out_dir <مسیر>` | فقط پوشه‌ی خروجی را جدا کن |

### گزینه‌های مفید

| گزینه | توضیح |
|---|---|
| `--granularity word` (پیش‌فرض) | یک مارکر بعدِ هر کلمه — برای هایلایتِ کلمه‌به‌کلمه |
| `--granularity sentence` | مارکر فقط در مرزِ جمله‌ها (بعدِ `.`/`!`/`?`) |
| `--device cuda` یا `--device cpu` | پیش‌فرض خودکار تشخیص می‌دهد |
| `--language eng` | پیش‌فرض همین است؛ برای زبانِ دیگر کدِ ISO 639-3 بدهید |



## نکته‌ی مهمِ لایسنس (نه مشاوره‌ی حقوقی)

مدلِ پیش‌فرضِ align (`MahmoudAshraf/mms-300m-1130-forced-aligner`) با لایسنسِ **CC-BY-NC-4.0** (غیرِ تجاری) منتشر شده — نه خودِ کتابخانه (که BSD است)، بلکه فقط وزن‌های مدل. از آن‌جا که این مدل فقط **آفلاین برای تولیدِ داده‌ی زمان‌بندی** استفاده می‌شود و در اپِ نهایی توزیع نمی‌شود، ریسکِ عملی احتمالاً کم است، ولی چون اپِ شما تجاری/فروشی است، بهتر است خودتان این نکته را بررسی کنید (من وکیل نیستم و این توصیه‌ی حقوقی نیست). اگر خواستید احتیاط کنید، مدل‌های جایگزینِ wav2vec2 با لایسنسِ آزادتر (مثلِ نسخه‌های عمومیِ `facebook/wav2vec2-base-960h`) هم با `--alignment_model` قابلِ استفاده‌اند، هرچند دقتشان برای این کارِ خاص تست نشده.

## ذخیره در گیت + راه‌اندازیِ خودکار روی سیستمِ جدید

بله، می‌شود — ولی چند نکته:

- **چیزی که در گیت می‌رود:** خودِ کدها (`align_batch.py`)، `requirements.txt`، `setup.ps1`، و این README. فایلِ `.gitignore` (کنارِ همین‌ها) این‌ها را کنار می‌گذارد: `.venv/` (خودِ محیطِ مجازی — چندصد مگابایت و کاملاً وابسته به سیستمِ نصب‌شده، هیچ‌وقت نباید در گیت برود)، `__pycache__/`، و پوشه‌ی `output/` (خروجی‌های تولیدشده). اگر می‌خواهید فایل‌های صوتی/متنیِ خودتان (`audio/`, `text/`) هم در گیت باشند تا روی سیستمِ دیگر هم موجود باشند، آزادید — فقط اگر صداها حجیم‌اند بهتره یا کنار بگذارید (gitignore) یا با Git LFS مدیریت کنید (گیتِ معمولی برای فایل‌های باینریِ بزرگ مناسب نیست).

- **چیزی که در گیت *نمی‌رود* ولی روی سیستمِ جدید لازم است دستی نصب شود:** خودِ Python، خودِ Git، و خودِ FFmpeg — این‌ها برنامه‌های سیستم‌عامل‌اند، نه چیزی که با pip/git بشود «همراهِ پروژه» فرستاد. هیچ راهی نیست که کلونِ یک ریپو این‌ها را خودکار نصب کند؛ همیشه یک قدمِ دستی (یا حداقل یک winget/دانلود) باقی می‌ماند.

- **`setup.ps1`** دقیقاً همان کاری را خودکار می‌کند که تا این‌جا با هم دستی انجام دادیم: چک‌کردنِ Python/Git/FFmpeg (با پیامِ راهنما اگر نبودند)، ساختنِ `.venv`، و `pip install -r requirements.txt`. روی سیستمِ جدید، بعدِ `git clone`، فقط کافی‌ست:
  ```powershell
  cd align_engine
  .\setup.ps1
  ```
  (اگر خطای اجرای اسکریپت داد، همان دستورِ `Set-ExecutionPolicy` که قبلاً برای activate هم لازم شد را بزنید.)

فایلِ به‌روزشده (`.gitignore` + `setup.ps1` + همین README) را ضمیمه کردم.

## اگر تعدادِ کلماتِ خروجی با متن جور در نیامد

اسکریپت با خطا متوقف می‌شود و می‌گوید صدا و متن دقیقاً مطابقت ندارند (کلمه‌ی اضافه/کم، یا فایلِ اشتباه جفت شده). قبل از اجرای batch، مطمئن شوید متنِ هر فایل دقیقاً همان چیزی است که گوینده می‌گوید.
